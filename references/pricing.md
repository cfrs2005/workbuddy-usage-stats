# 价目表说明

`config/pricing.json` 是成本估算的唯一数据源。脚本不会去网上抓价——价格必须由人核实后写进来，因为 API 定价页随时会变，而抓取拿到的可能是旧缓存或三手转载。

## 字段

```json
"deepseek-v4.1-flash": {
  "cache_hit": 0.003,          // 缓存命中输入，USD / 1M tokens
  "cache_miss": 0.15,          // 缓存未命中输入
  "output": 0.6,               // 输出
  "peak_multiplier": 2.0,      // 高峰价相对闲时的倍数
  "peak_windows_utc": [[1,4],[6,10]],   // 高峰窗口（UTC 小时，左闭右开）
  "peak_weekdays_only": true,  // 仅工作日高峰，周末全闲时
  "note": "…",
  "source": "https://…",
  "verified_at": "2026-09-18"
}
```

没有分时定价的模型，省略 `peak_multiplier` 和 `peak_windows_utc` 即可。

## 三档价格的意义

缓存命中价往往比未命中价低 1–2 个数量级（DeepSeek 是 50 倍）。所以**同一个模型，缓存率 99% 和 5% 的实际成本能差十倍以上**。

估算时三档必须分开算：

```
成本 = 命中token/1e6 × cache_hit
     + 未命中token/1e6 × cache_miss
     + 输出token/1e6 × output
```

用单一「平均输入价」会把成本算错方向——缓存率高的用量会被高估，缓存率低的反被低估。

## 分时定价（目前只有 DeepSeek）

DeepSeek 的官方卡是两档：

- 高峰 = 闲时 × 2
- 高峰窗口：周一至周五 `01:00–04:00` 与 `06:00–10:00` UTC，即北京时间 `09:00–12:00` 与 `14:00–18:00`
- 周末与国内法定节假日全天按闲时

`estimate_cost.py` 逐条 trace 判断时间戳落在哪个窗口，而不是对整天取均价。这样长会话跨窗口时会有少量误差，但远小于用均价。

## 已知的坑

| 模型 | 坑 |
|---|---|
| gpt-6.1-sol | 还有 cache **write** 费（$2.50/M）没有计入；输入超 272K 时整个请求按 2× 输入 / 1.5× 输出计费，本表按标准档算 |
| step-5-preview | 国内价与海外价不同，表里取海外档；WorkBuddy 曾有限时免费期，那段时间实际为 0 |
| space-bunny | 无公开 API 定价，标为 null，脚本会给「无公开价」而不是编一个 |
| hy4-preview | 国内价为 0.3 / 6 / 18 元每百万，表里取美元档 |

## 更新方法

1. 打开各家官方定价页（`source` 字段里有链接）
2. 核对三档价格与分时规则
3. 改 `pricing.json`，更新 `verified_at`
4. 重跑 `estimate_cost.py`，对比旧结果，确认变化符合预期

价格变动频繁，做预算前务必复核。
