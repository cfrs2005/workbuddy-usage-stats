# 积分机制与标定方法

## 积分是什么

WorkBuddy 不按 token 直接收费，按**积分**（credits）扣。用户看到的是模型菜单里那个 `0.11x`、`1.56x` 之类的数字，叫**消耗倍率**。

```
积分 = 倍率 × 用量
用量 ∝ token 数 × 上下文长度 × 工具调用轮次
```

关键认知：**倍率是单价系数，不是能力评分，也不管总量。**

一个挂 0.11x 的模型跑 50 轮长任务，完全可能比 1.62x 模型的三句话问答更贵。

## 倍率从哪读

可靠来源只有一处：客户端本地配置。

```
~/.workbuddy/local_storage/entry_*.info
  → [].data.models[].credits   // 形如 "x0.11"、"x0.00"
```

`estimate_credits.py` 会自动扫这些文件，取「模型条目最多」的那份作为倍率表。

**为什么不用二手文章**：这些价格随运营活动调整，文章发布即开始过期。实测中同一模型在文章里写 0.43x、客户端里是 0.33x。

### 名称不一致

trace 里的模型名和客户端 id 可能不同。目前已知一处：

```python
ALIASES = {
    "kimi-k3.1-highspeed": "kimi-k3.1-pro-highspeed",
}
```

新发现的别名补进 `estimate_credits.py` 的 `ALIASES`。

### 峰谷折扣

部分模型在非高峰时段倍率减半：

```python
NIGHT_HALF = {"deepseek-v4.1-flash", "deepseek-v4-pro"}
```

例如 deepseek 白天 0.11x、夜间 0.055x。脚本按 trace 时间戳逐条判断。

## 绝对积分怎么算

官方没有公开「1.0x 倍率 = 多少积分 / 百万 token」，所以需要一个**锚点**：

```
K = 实测积分 ÷ (倍率 × 用量百万数)

某模型估算积分 = 加权token百万数 × K
```

### 本项目实测

- 锚点：kimi-k3.1-highspeed 一次会话约 2000 积分
- 该会话用量：4,189,465 token，倍率 1.56
- 推出 **K ≈ 306 积分 /(倍率·百万 token)**
- 全月 7 模型合计约 **10,181 积分**

### 误差说明

| 来源 | 影响 |
|---|---|
| 锚点是「大概 2000」 | 若实际 1800/2200，全表等比缩放 ±10% |
| 单次采样 | 单个会话的轮次构成未必代表平均水平 |
| 用量只按 token 估 | 上下文长度与工具轮次的影响被平均掉了 |

所以：**K 值算出来的数字只能用于量级判断和模型间相对倍数，不能当账单。**

想知道更准的，多给几个实测样本（不同模型、不同任务类型），K 会收敛。

## 积分折算成钱

两种口径，差一倍：

| 口径 | 单价 | 1 万积分约 |
|---|---|---|
| 加量包零售价 | 1000 积分 = ¥50 | ¥500 |
| 套餐内含 | 高级版 ¥199 / 9000 积分 ≈ ¥0.022 | ¥225 |

报数字时要说清按哪种算，否则容易被理解成实际支出。

## 和 API 直连价的关系

两者不是一回事。实测同一批用量：

- API 直连等价成本：约 $13（¥94）
- 积分按零售价折算：约 ¥509

差 5.4 倍。这中间的差价不完全等于加价——它包含 Agent 编排、工具调用、上下文存续这些平台侧的东西。比较时别拿裸 API 价当基准骂平台。
